# Fertiliser dose (kg/ha)

The ranking answers *which* fertiliser. This document covers the layer that
answers *how much*, which is what a farmer actually spends money on.

Everything in it is read from the ICAR documents already shipped in
`backend/data/icar/`. Nothing is generated by an LLM and nothing is
interpolated beyond the rules printed beside each number.

## Where every number comes from

| Number | Source |
|---|---|
| Recommended dose of N, P₂O₅, K₂O and S per crop (kg/ha) | **FertiSolver user manual, Appendix-A, p22-23** |
| Urea split percentages T1-T4 | Same manual, p23 (stage definitions and split table) |
| Fertiliser grades: DAP 18:46:0, urea 46:0:0, MOP 0:0:60, SSP 0:16:0, SOP 0:0:50, 12:32:16, 14:35:14 | Same manual, Table 3, p17 |
| Soil test categories: N <282 / 282-560 / >560, P <34 / 34-68 / >68, K <108 / 108-280 / >280 kg/ha, pH <6.5 / 6.5-7.5 / >7.5 | Same manual, Table 1, p13 |
| Low/high adjustment of the printed dose | **ICAR-IISS INM manual, p36**: the printed dose applies to the *medium* category, with "an arbitrary adjustment (decrease or increase by 25-50 per cent) for high and low categories". This layer takes the conservative end: **+25% low, −25% high** |
| Lime rate | The manual's worked example, p19: 400 kg/ha of lime at pH 5.5, scaled linearly (one pH unit below 6.5 = 400 kg/ha) |

## The calculation

1. Look up the crop's ICAR row (e.g. rice → `rice-midland` 80:40:20).
2. Classify the soil's N, P and K as low/medium/high.
3. Scale the printed dose by the adjustment factor.
4. Convert nutrient requirement into product kilograms:
   - sulphur first, through SSP (0:16:0, 11% S), which also pays part of P₂O₅;
   - remaining P₂O₅ through DAP (18:46:0), whose starter N is credited;
   - K₂O through MOP (0:0:60);
   - the N balance through urea (46:0:0), split on the manual's T1-T4 schedule.

Example — wheat, pH 5.2, N 120 / P 55 / K 30 (acid soil):

| Product | kg/ha | Supplies |
|---|---|---|
| Lime | 520 | pH amendment (before the crop fertiliser) |
| DAP | 130.4 | 23.5 N · 60 P₂O₅ |
| Muriate of Potash | 83.3 | 50 K₂O |
| Urea | 275.0 | 126.5 N, split T1 137.5 / T2 68.8 / T3 68.8 |

## How the soil is classified

This is the part that is easy to get wrong, so it is explicit in the code:

- **The farmer's own soil test** (N/P/K supplied in the request) is classified
  against ICAR Table 1 thresholds.
- **A district with no soil test** is classified from the DES survey's own
  low/medium/high *sample counts* — the same three-band protocol the ICAR
  tables use. The survey's smoothed kg/ha estimate is never thresholded: it is a
  band-share midpoint, not a laboratory value, and treating it as one would have
  reported almost every district as low-N.
- **Nothing measured at all** (unknown district, no soil card) stays on the
  printed dose for the medium category. The 90/40/40 fallback is a neutral
  default, not a measurement, so it does not trigger the +25% low-soil
  adjustment.

## Coverage

36 ICAR rows are encoded, covering 19 of the app's 24 crops (rice, wheat, maize,
soybean, chickpea, pigeon pea, green gram, black gram, lentil, groundnut,
mustard, sunflower, potato, tomato, onion, chilli, jowar, bajra, ragi) plus the
manual's other field, oilseed and vegetable rows.

**Cotton, sugarcane, turmeric, ginger and barley have no row in Appendix-A.**
They return `available: false` with that reason and no kilogram figure. A guessed
cotton dose (the common 60:30:30 is not in this corpus) would be
indistinguishable from a sourced one once it is on screen, which is worse than
an honest gap. The soil status reading for those crops is still computed.

Also deliberately excluded:

- **STCR prescription equations** (IISS manual p37, e.g.
  `FN = 6.38 T − 0.63 SN − 1.42 ON`). They need district calibration constants
  and a yield target that this platform does not hold.
- **A gypsum rate** for basic soils: the manual gives none, so the response says
  so instead of inventing one.
- **Cost.** Appendix-B lists 2021 prices; quoting them as today's cost of the
  dose would mislead, so the dose stays in kilograms.

## Determinism

`backend/fertilizer_dose.py` has no randomness, no network calls and no LLM. The
same crop and soil return the same kilograms on every request; a test asserts it
across five runs and across two HTTP calls.

## Reproduce

```bash
cd backend && ../.venv/bin/python -m pytest tests/test_fertilizer_dose.py -q
```

The endpoint returns the whole object under `dose`, including the product list,
the urea schedule, the requirement, which basis classified each nutrient, and
the citations with page numbers.
